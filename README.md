# Sports Event Planner Platform

Clean Architecture microservices starter for a sports event planner platform.

## Services

- `auth-service`
- `event-service`
- `notification-service`
- `api-gateway`

## Local Workflow

```bash
make tidy
make test
make test-integration
make docker-up
make migrate-up
```

Prometheus runs on `localhost:9090`, Alertmanager on `localhost:9093`, Grafana on `localhost:3000`, NATS monitoring on `localhost:8222`, and the API gateway on `localhost:8080`.

`make test-integration` runs the Docker Compose-backed end-to-end suite with isolated Postgres, Redis, and NATS services, then tears the stack down.

## Live API Demo

Start the full backend and monitoring stack:

```bash
docker compose up -d
docker compose ps
```

Service URLs:

- API Gateway: `http://localhost:8080`
- Grafana: `http://localhost:3000` (`admin` / `admin`)
- Prometheus: `http://localhost:9090`
- Alertmanager: `http://localhost:9093`
- NATS monitoring: `http://localhost:8222`

The event database is seeded by migrations with demo events such as Football Match Astana Arena, Basketball Training Session, Volleyball Meetup, Marathon Preparation, and Tennis Tournament. The seed uses deterministic IDs and `ON CONFLICT DO NOTHING`, so restarts do not create duplicates.

### Postman Flow

Create a Postman environment with:

- `base_url`: `http://localhost:8080`
- `access_token`: set this from the login response
- `user_id`: set this from the login response
- `event_id`: set this from the create event response

1. Register

`POST {{base_url}}/v1/auth/register`

```json
{
  "email": "demo.presenter@example.com",
  "password": "password123",
  "role": "student"
}
```

Expected: `200 OK` with `user_id`, `access_token`, and `refresh_token`.

2. Login

`POST {{base_url}}/v1/auth/login`

```json
{
  "email": "demo.presenter@example.com",
  "password": "password123"
}
```

Expected: `200 OK`. Save `access_token` as `{{access_token}}` and `user_id` as `{{user_id}}`.

For all protected requests, use:

`Authorization: Bearer {{access_token}}`

3. View seeded events

`GET {{base_url}}/v1/events?page=1&page_size=10`

Expected: `200 OK` with seeded sports events and current `participants_count`.

4. Create event

`POST {{base_url}}/v1/events`

```json
{
  "sport": "football",
  "category": "match",
  "competition": "live demo cup",
  "title": "Live Demo Football Match",
  "description": "Postman-created event for the live backend demo.",
  "location": "Demo Stadium",
  "start_time": "2026-07-01T10:00:00Z",
  "end_time": "2026-07-01T12:00:00Z",
  "country": "kz",
  "city": "almaty",
  "max_participants": 8
}
```

Expected: `200 OK` with `event.id`. Save it as `{{event_id}}`.

5. Get single event

`GET {{base_url}}/v1/events/{{event_id}}`

Expected: `200 OK` with the created event.

6. Update event

`PUT {{base_url}}/v1/events/{{event_id}}`

```json
{
  "sport": "football",
  "category": "match",
  "competition": "live demo cup",
  "title": "Updated Live Demo Football Match",
  "description": "Updated during the live API demo.",
  "location": "Demo Stadium",
  "start_time": "2026-07-01T11:00:00Z",
  "end_time": "2026-07-01T13:00:00Z",
  "country": "kz",
  "city": "almaty",
  "max_participants": 10
}
```

Expected: `200 OK` with the updated title and capacity. Updating seeded events with a demo user should return `403 FORBIDDEN`, which demonstrates ownership checks.

7. Join event

`POST {{base_url}}/v1/events/{{event_id}}/join`

```json
{}
```

Expected: `200 OK`; `participants_count` increases.

8. Leave event

`POST {{base_url}}/v1/events/{{event_id}}/leave`

```json
{}
```

Expected: `200 OK`; `participants_count` decreases.

9. View notifications

`GET {{base_url}}/v1/users/{{user_id}}/notifications`

Expected: `200 OK` with notifications generated by event create, update, and join actions.

10. Delete event

`DELETE {{base_url}}/v1/events/{{event_id}}`

Expected: `200 OK` with `deleted: true`. A later `GET` should return `404 EVENT_NOT_FOUND`.

### Notification Demo

Watch notification logs while creating, updating, and joining events:

```bash
docker compose logs -f event-service notification-service
```

Expected log messages include:

- `event created`
- `event updated`
- `event joined`
- `nats event published`
- `nats event consumed`
- `[MOCK NOTIFICATION]`
- `notification sent`

The notification service intentionally uses a safe mock/logging fallback when Mailgun is not configured, so the demo remains reliable without real email delivery.

### Monitoring Demo

Open Grafana at `http://localhost:3000` and use the `Sports Event Planner` folder:

- `Sports Services Overview`: HTTP traffic, gRPC traffic, p50/p95/p99 latency, errors, and business metrics.
- `Sports Capacity Planning`: CPU, memory, goroutines, gRPC method traffic, and NATS flow.
- `Sports Alerts`: target health and alert states.

During the Postman flow, these metrics should visibly move:

- `sports_planner_http_requests_total`
- `sports_planner_grpc_server_requests_total`
- `sports_planner_events_created_total`

Prometheus targets should stay healthy at `http://localhost:9090/targets`.

## API Gateway Routes

Public:

- `POST /v1/auth/register`
- `POST /v1/auth/login`
- `POST /v1/auth/refresh`

Protected with `Authorization: Bearer <token>`:

- `GET /v1/auth/me`
- `POST /v1/events`
- `GET /v1/events/:id`
- `GET /v1/events`
- `PUT /v1/events/:id`
- `DELETE /v1/events/:id`
- `POST /v1/events/:id/join`
- `POST /v1/events/:id/leave`
- `POST /v1/notifications`
- `POST /v1/events/:id/reminders`
- `GET /v1/users/:id/notifications`

Operational:

- `GET /healthz`
- `GET /readyz`
- `GET /metrics`

The gateway uses Gin for REST routing and typed gRPC clients for service-to-service calls. The current stubs are intentionally minimal and use the shared JSON gRPC codec in `pkg/grpcx` so the skeleton compiles and runs without requiring local protobuf codegen plugins.
